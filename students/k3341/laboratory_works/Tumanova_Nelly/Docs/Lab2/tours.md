# Приложение `tours`

## Назначение

Приложение `tours` — центральное приложение системы, отвечающее за хранение туров, управление датами выездов (отправлениями), резервирование туров клиентами и подтверждение заявок сотрудниками. Приложение реализует как клиентскую, так и административную части: клиенты просматривают туры, подают и отзывают заявки, просматривают историю поездок; сотрудники (staff) создают туры, добавляют даты выездов и управляют статусами резервирований.

---

## Модель данных

### `Country` — страна

| Поле | Тип | Описание |
|------|-----|----------|
| `name` | CharField(60) | Название страны |

`__str__()` возвращает название страны.

### `Tour` — тур

| Поле | Тип | Описание |
|------|-----|----------|
| `title` | CharField(200) | Название тура |
| `countries` | ManyToManyField(Country) | Страны маршрута |
| `description` | TextField | Описание тура |

`__str__()` возвращает название тура.

### `Departure` — выезд (отправление)

Конкретная дата проведения тура.

| Поле | Тип | Описание |
|------|-----|----------|
| `tour` | ForeignKey(Tour, CASCADE) | Тур, к которому относится выезд |
| `start_date` | DateField | Дата начала |
| `end_date` | DateField | Дата окончания |

`__str__()` возвращает строку вида `Название тура (дата–дата)`.

### `Reservation` — резервирование (заявка)

| Поле | Тип | Описание |
|------|-----|----------|
| `user` | ForeignKey(User, SET_NULL, null=True) | Клиент, подавший заявку |
| `departure` | ForeignKey(Departure, RESTRICT, null=True) | Выезд, на который подана заявка |
| `status` | CharField(choices) | Статус заявки |
| `comment` | TextField(null, blank) | Комментарий |
| `created_at` | DateTimeField(auto_now_add) | Дата подачи заявки |

**Статусы (`Reservation.Status`):**

| Значение | Отображение |
|----------|-------------|
| `pending` | Ожидает подтверждения |
| `confirmed` | Подтверждена |
| `rejected` | Отклонена |

`__str__()` возвращает строку вида `пользователь reserves выезд`.

Все четыре модели зарегистрированы в Django-admin.

## Формы

Обе формы используют миксин `StyledFormMixin`, добавляющий CSS-класс `input` всем полям.

| Форма | Модель | Поля | Подписи |
|-------|--------|------|---------|
| `TourForm` | `Tour` | `title`, `countries`, `description` | «Название тура», «Страны тура», «Описание тура» |
| `DepartureForm` | `Departure` | `start_date`, `end_date` | «Дата начала поездки», «Дата окончания поездки» |

Префикс приложения — `tours:`. Определены в `tours/urls.py`:

| URL | Имя | View | Доступ |
|-----|-----|------|--------|
| `/` | `available` | `TourListView` | Авторизованные |

| `/add/` | `create` | `StaffTourCreateView` | Staff |
| `/<int:pk>/` | `detail` | `TourDetailView` | Авторизованные |

| `/history/` | `history` | `ClientHistoryView` | Авторизованные |

| `/departure/` | `departures` | `StaffDepartureListView` | Staff |

## Представления (Views)

### Миксин `StaffRequiredMixin`

Комбинирует `LoginRequiredMixin` и `UserPassesTestMixin`; `test_func` возвращает `request.user.is_staff`. Используется для всех административных представлений.

### Клиентские представления

**`TourListView`** (`available_tours.html`)
Список доступных туров. Формирует queryset из туров, у которых есть будущие выезды (`start_date > today`), исключая выезды, на которые текущий пользователь уже подал заявку. Использует `Prefetch` для оптимизации и `distinct()`. Поддерживает поиск по названию и описанию (`search`). Пагинация — по 3 тура.

**`TourDetailView`** (`tour.html`)
Детальная страница тура. Для клиента показывает будущие выезды, на которые он ещё не подавал заявку; для staff — все выезды. Также выводит отзывы о туре (`Review` из приложения `reviews`) с сортировкой по дате и средний рейтинг (`Avg('rating')`).

`post()` обрабатывает добавление новой даты выезда сотрудником: валидирует `DepartureForm`, привязывает выезд к туру и сохраняет. Клиентам POST запрещён (редирект на детальную страницу).

**`ClientUpcomingTripsView`** (`upcoming_list.html`)
Список текущих заявок пользователя на выезды с `end_date >= today`. В шаблоне доступна кнопка отзыва заявки.

**`ReserveDepartureView`**
POST-представление: создаёт `Reservation` со статусом `pending` через `get_or_create` (защита от дублей), затем редирект на `upcoming`.

**`CancelReservationView`**
POST-представление: удаляет резервирование, принадлежащее текущему пользователю (`user=request.user`), редирект на `upcoming`.

**`ClientHistoryView`** (`history.html`)
История завершённых поездок: резервирования с `end_date < today`, исключая отклонённые. Дополнительно формирует множество `user_reviewed_departure_ids` — ID выездов, на которые пользователь уже оставил отзыв, чтобы в шаблоне показать «Отзыв оставлен» вместо кнопки.

### Административные представления (staff)

**`StaffTourListView`** (`all_tours.html`)
Все туры агентства без фильтра по датам, с поиском по названию/описанию. Пагинация — по 3.

**`StaffTourCreateView`** (`tour_create.html`)
Создание нового тура через `TourForm`, после успеха — редирект на `tours:all`.

**`StaffDepartureListView`** (`departures.html`)
Список всех выездов, сортировка по `-start_date`, поиск по названию/описанию тура.

**`StaffDepartureDetailView`** (`departure.html`)
Детали выезда: список заявок с данными пользователя и датой подачи. `post()` обрабатывает смену статуса конкретной заявки: находит `Reservation` по `id` и `departure`, обновляет `status`, редирект обратно на страницу выезда.

| Шаблон | Назначение |
|--------|------------|
| `available_tours.html` | Клиентский список доступных туров |
| `all_tours.html` | Административный список всех туров + кнопка «Добавить тур» |
| `tour.html` | Детальная страница тура: страны, описание, выезды, форма добавления выезда (staff), отзывы и рейтинг |
| `tour_create.html` | Форма создания тура |
| `departures.html` | Список выездов (staff) |
| `departure.html` | Детали выезда и управление статусами заявок (staff) |
| `upcoming_list.html` | Текущие заявки клиента + кнопка отзыва |
| `history.html` | История завершённых поездок + кнопка «Оставить отзыв» |
| `pagination.html` | Переиспользуемый блок пагинации (первая/назад/вперёд/последняя, сохраняет `search`) |

### Особенности шаблонов

- Все шаблоны наследуют `base.html`.
- Единый цикл вывода полей формы с блоком ошибок (`filled--error`).
- Общие CSS-классы: `horizontal-layout`, `vertical-layout`, `filled`, `button`, `button--dark`, `tag`, `input`, `centered`, `wide`, `fit-content`.
- Пагинация вынесена в отдельный включаемый шаблон и сохраняет параметр `search` при переходах.
- Разграничение интерфейса по `user.is_staff`: staff видит административные элементы (добавление выездов, управление заявками), клиент — кнопки «Подать заявку», «Отозвать заявку».

## Взаимодействие с другими приложениями

- **`users`** — `Reservation.user` ссылается на `users.User`; в шаблонах используются данные пользователя (логин, имя, фамилия, email).
- **`reviews`** — на детальной странице тура выводятся отзывы `Review` и средний рейтинг; в истории поездок проверяется наличие отзыва по выезду и формируется ссылка на `reviews:add`.

---

## Безопасность и разграничение доступа

- Все представления требуют авторизации (`LoginRequiredMixin`).
- Административные операции доступны только staff (`StaffRequiredMixin`).
- Отзыв и удаление заявки возможны только для собственных резервирований (`user=request.user`).
- Формы защищены CSRF-токеном.
- `get_or_create` предотвращает дублирование заявок на один и тот же выезд.
